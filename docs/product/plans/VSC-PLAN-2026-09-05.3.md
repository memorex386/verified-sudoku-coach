# Local playable tutor first

The maintainer approved a smaller first milestone on 2026-09-05. This amendment supersedes
the immediate delivery sequence in [the portability plan](VSC-PLAN-2026-09-04.2.md), preserving
deterministic authority, inward dependencies and separate merge/spend/deployment authorization.
Prior plans and checkpoints remain historical records.

## First milestone: a local deterministic tutor

Deliver one usable session before further standalone infrastructure work:

- One original seed-generated, independently checked unique 9x9 puzzle that can be completed
  using naked and hidden singles. Select the first qualifying attempt from 0 through 999999;
  exhaust the search explicitly rather than substituting a borrowed or unsolved puzzle. The
  existing generation algorithm is reused; advanced-technique and 27–30-clue showcase filters
  are not local-tutor requirements. Keep the seed and regeneration test with the puzzle.
- A local playable board with value entry, notes, clear and undo. Player notes never determine
  candidates. A conflicting move can be undone; the tutor does not reason from contradictory input.
- Explicit **Get help** opens the bottom sheet from the saved
  [interaction concept](../concepts/coach-interaction.md). Offer a nudge, a stronger hint and an
  explanation with highlights derived from verified facts. The player places the number.
- Deterministic templates first. No model call, background observer, account or production service
  is needed to test whether this interaction helps the maintainer.

Use the local search profile `local-singles/v1`: naked singles in row-major order, then hidden
singles in rows, columns and boxes, ordered by unit index then digit. Detectors propose;
independently callable verifiers recompute premises from authentic immutable board state.
Reject malformed, stale, contradictory and false proposals. No arbitrary candidate-mask setter
or elimination support is introduced. If no supported hint exists, show an explicit unsupported
state; never claim a complete `classic-six/v1` search or manufacture a deduction. Existing V1
proof/replay schemas and the six-technique ruleset are unchanged; this profile is a local subset.

The first milestone is complete when the maintainer can launch it locally, play the generated
puzzle to completion, request all three hint depths, see the correct cells highlighted, recover
from a conflict, and continue playing after dismissing a hint. Changing the board cancels stale
lessons and animations. Include keyboard controls, visible focus and reduced-motion behavior.
Focused proof, puzzle-regeneration and browser tests plus `npm run verify` are required.
The launch and browser-test commands will be `npm run dev:tutor` and `npm run test:tutor`;
`npm run test:proof` covers the independently verified singles. Implement commands with their slices.

## Private gate and release boundary

For this isolated local milestone only, the private aggregate command is not a prerequisite for
implementing the two single techniques. This is the maintainer's explicit scope change, not a
private conformance pass. Generated positive, negative, tamper, stale and deterministic tests
must establish the limited local behavior. Private boards, hashes and source remain excluded.

The private command and linked evidence remain mandatory before private integration, parity
claims, or acceptance of the full six-technique engine/showcase. Its frozen baseline is unchanged.
The local puzzle is not `showcase-v1`; it supplies no difficulty, learning or product-quality claim.

WP-2026-003 remains the active package and may deliver this local milestone across its existing
core/tooling surfaces, minimal deterministic lesson code in `packages/coach-core`, and local UI
in `apps/replay-web`. Later packages stay Draft. Local completion does not mark WP-2026-003 Done
or satisfy the full release catalog; the deferred gates remain recorded rather than relabeled.

## After trying the tutor

The next checkpoint is one model through one local server, called only for explicit help and
limited to verified teaching options. Validate model-selected references, discard stale results,
keep credentials out of the browser, bound calls/spend and offer explicit recovery. Existing
provider/privacy policies apply. Implement that checkpoint after reviewing the deterministic
tutor; live calls still require separate spend authorization.

Defer the other four techniques, automatic interventions, persistent learner profiles, recaps,
voice, alternate providers, comparative studies, elaborate showcase selection, public replay/case
study, Firebase/accounts, deployment and reviewer pilot. Keep independent verification, unique
generated inputs, truthful failures and minimal regression tests from the beginning.
